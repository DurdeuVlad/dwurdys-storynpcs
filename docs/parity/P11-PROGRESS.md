## P11-1 — CustomNPCs import contract (#91)

`migration/` — real migration path that does not pretend the engine JAR contains
creator world data:

- `ImportSource`: explicit source kinds. `STORYNPCS_YAML_PACKAGE`,
  `STORYNPCS_JSON_PACKAGE`, `TEMPLATE_PACKAGE` are supported;
  `TARGET_WORLD_NBT` / `CUSTOMNPCS_TEXT_EXPORT` are `UNSUPPORTED_NEEDS_EVIDENCE`
  with named reasons — the register's needs-input state, honored.
- `FieldMappingRegistry`: every top-level field classified
  `DIRECT` / `MIGRATED` / `UNSUPPORTED` / `UNKNOWN` / `ENVELOPE` with a
  `P0-1` evidence reference. `scripts`/`linkedData`/`scriptData` are reported
  UNSUPPORTED — never silently dropped. Unknown fields fail closed.
- `DefinitionImporter`: `plan()` produces a deterministic, ordered
  `ImportPlan` (sorted by family/file; probe-loads through the real schema
  loader into a scratch registry so intra-package duplicates and schema errors
  quarantine per document). `dryRun()` reports `WOULD_APPLY` with zero writes.
  `apply()` executes through an `ImportSink` — the canonical service boundary
  in production — with REPLACE snapshots and full rollback
  (`RESTORED`/`ROLLBACK_INCOMPLETE` recorded).
- Conflict policies: `FAIL` (aborts before any write), `SKIP`, `RENAME`
  (deterministic `__import<N>`, intra-plan collision-safe), `REPLACE`
  (overwrite with snapshot). Re-imports are idempotent: same package + `SKIP`
  yields all `SKIP_CONFLICT`.
- `ImportReport`: per-step outcomes, field mappings, conflicts, quarantines,
  rollback outcome, deterministic `summaryMap()` for CLI/UI adapters.
