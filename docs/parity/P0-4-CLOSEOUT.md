- Added `tools/parity/fixture_harness.py` and `tools/parity/test_fixture_harness.py`.
- The current exact fixture-ID-to-JUnit-case map covers all 25 fixtures, with explicit tested and uncovered scopes. Partial mappings remain labeled with their uncovered behavior; no unrelated selector is used to make the fixture map appear complete. Mapped pass/fail/skipped/missing outcomes remain distinct.
- Added `tools/parity/run_storynpcs_fixtures.py`. One command first invalidates the exact prior parity report files, clears Gradle's generated test outputs with `cleanTest`, runs the unfiltered full test suite, and accepts no XML if Gradle or the adapter fails. Success writes selected test outcomes and coverage limits plus the expanded failure-context report under `build/reports/parity/`; failure writes failure-only artifacts. It reads only the repository's standard Gradle result directory, which `cleanTest` clears; it has no alternate stale-report input path.

- Added parity tooling to CI: the Python parity unit suite runs on every pull request and main-branch build, after the documentation truth gate. The no-provenance structural CLI is intentionally not a required step because it is fail-closed/nonzero when its three source inputs are absent; the combined runner performs the same full catalog/manifest validation.
- CI runs the combined StoryNPCs fixture command with `--ci-allow-declared-blockers`. That mode cannot report parity PASS: it accepts only a clean mapped JUnit execution and the exact owner-linked blocker set, records `ci_validation_status=PASS` while overall fixture status and parity remain `BLOCKED`, and fails for any mapped failure, skip, missing selector, provenance failure, catalog error, or unexpected blocker. The default runner remains strict and exits nonzero when required source provenance is unavailable, even when all fixture selectors are mapped.
- Covered all 15 operation families and all 22 target domains from the traceability register.
- Integrated every catalog fixture with the P0-3 evidence gate and structured failure context.
- Locked the catalog baseline to unavailable target probes so catalog edits cannot forge runtime parity.
- `run_catalog` verifies the exact target JAR name, SHA-1, and SHA-256; binds GUI, packet, command, persistence-participant, and persistence-store rows to the pinned clean research inventories; and checks every listed decompiled-source hash and target-JAR class entry, including all persistence-store source files.
