## 2026-09-23 acknowledged-failure retry review

Planck returned `INCOMPLETE`, not approval. Its concrete P2 finding was that a server response for a rejected save/delete left the payload-bound key active, while `executeCanonicalMutation` caches the first result—including errors. Thus an acknowledged transient write failure followed by another click with unchanged content replayed the original failure forever. The review also explicitly left full `StoryNpcsClient` response routing, screen-level behavior, and several Minecraft-bound handler cases unchecked.

The local fix adds `PayloadBoundRequestId.acknowledge(UUID)`, which resets state only for the current response ID. Each of the five editor handlers now acknowledges matching success *or rejection*; stale IDs remain ignored. Timeout/lost-response retries retain their original key because no response has been acknowledged. A new service integration regression blocks NPC YAML writes with a filesystem obstruction, verifies the same-ID lost-response retry replays the cached rejection after the obstruction is removed, then acknowledges that result and proves the unchanged payload with a fresh ID commits to the registry and reloadable YAML. The focused helper/service test passed, then the full combined suite passed at 362/50. Independent review of this fix is pending.

Research basis: [Stripe documents](https://docs.stripe.com/api/idempotent_requests) that it saves the first result—including failures—and returns it for later uses of the same key; [AWS Well-Architected](https://docs.aws.amazon.com/wellarchitected/2025-02-25/framework/rel_prevent_interaction_failure_idempotent.html) recommends resending the same token when a client did not receive a response. Applying those patterns here, the next user click after an acknowledged rejection is a new logical attempt and needs a fresh key; keeping the key while unanswered preserves safe transport retry. This last client-lifecycle distinction is the implementation inference from those sources and StoryNPCs' cached-result behavior.
